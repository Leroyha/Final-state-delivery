# 案例：没有东坡肉的番茄炒蛋

[English](tomato-egg.md) | [简体中文](tomato-egg.zh-CN.md)

## 案例概述

一段公开讨论用做菜比喻描述 AI 编程失败：用户让 Agent 准备一盘简单的番茄炒蛋，Agent 却加入了无关的菜品。用户要求删除后，Agent 移除了实现，却继续把被否决的想法写入标题、注释、测试、文档和后续解释。

这个比喻的反差在于：不需要的成分从结果中消失，却在开发过程里变得更加显眼。

## 对应关系

| 做菜故事 | AI 辅助开发对应物 |
| --- | --- |
| 无关成分 | 未请求的功能、依赖或架构 |
| 用户要求删除 | 作用域纠正 |
| 从菜中移除成分 | 删除实现 |
| 菜单解释不存在的成分 | 界面或文档残留 |
| 厨房制作检测器 | 无依据的验证器或永久防护 |
| 菜谱记住事故 | 持久化记忆污染 |

## 正确的最终状态

最终产物应包含目标菜谱或功能。只有当前约束非直观且未来维护者确实需要时，才保留持久解释。事故本身应放在案例、问题记录或对话材料中，默认不应出现在产品表面。

## 比喻的价值

它清晰展示三条边界：

1. 删除实现不要求保留它的名称。
2. 局部纠正不会自动成为长期偏好。
3. 可靠结果不由 Agent 解释纠正的篇幅衡量。

## 比喻的限制

这是解释性类比，不是控制实验。它不能证明某一种认知机制解释所有模型输出。技术分析应使用限定性结论，并区分可能因素和已知工程观察。
