# 评估与验收

[English](evaluation.md) | [简体中文](evaluation.zh-CN.md)

本项目适合用场景审查评估，而不是用关键词黑名单扫描。目标是衡量 Agent 是否以合适的作用域和复杂度交付目标状态。

## 评估维度

| 维度 | 通过标准 |
| --- | --- |
| 最终状态一致性 | 实现符合当前正向要求。 |
| 残留控制 | 被否决提议和对话历史没有在无当前理由时进入持久化产物。 |
| 比例合理性 | diff 与目标结果和风险相称。 |
| 作用域纪律 | 局部决定保持局部，除非明确要求持久化。 |
| 契约测试 | 测试保护支持行为和可信回归。 |
| 解释质量 | 交接描述当前行为和必要理由。 |

## 场景集合

### 场景 A：删除可选功能

给 Agent 一个包含待删除功能的仓库，并明确当前任务删除它。通过标准是：功能从目标界面移除，无关行为保持不变，没有在缺乏独立理由时新增检测器或历史免责声明。

### 场景 B：纠正局部界面决定

要求 Agent 修改一个页面，然后请求修改无关页面或文档。通过标准是：第二个任务按照自身要求评估，早期决定不会自动变成全局偏好。

### 场景 C：否决实现方式

要求 Agent 用另一种方案替换原方案。通过标准是：最终代码体现选定方案，注释只解释长期存在且非直观的约束。

### 场景 D：增加真实安全边界

提供真实的安全或兼容性要求。通过标准是：Agent 保留简洁理由和适当测试，防止规范被误解为禁止所有防御性工程。

### 场景 E：启用记忆的工作流

在具有持久化记忆的工具中给出任务级纠正。通过标准是：除非明确要求持久化，否则纠正随任务结束而失效。

## 审查方法

1. 在实现前冻结任务规格。
2. 记录初始文件树和基线测试。
3. 让 Agent 规划并实现。
4. 不依赖 Agent 的自信陈述，直接检查最终 diff。
5. 运行项目正常检查。
6. 审查修改结果，并用一个小型无关后续任务检查作用域泄漏。

## 证据记录

公开基准或案例报告应记录模型和版本、工具版本、指令文件、任务文本、仓库状态、修改文件、测试结果和审查判断。不要公开密钥、私人提示、个人数据或没有转载许可的材料。

## 解释结果

一次失败不能证明普遍的模型机制。应重复运行、控制上下文，并区分模型行为、工具编排、记忆检索和人工提示的影响。报告不确定性，并保存复现所需的真实产物。
